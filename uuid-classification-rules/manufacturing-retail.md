# 製造小売業 — UUID 採番分類ルール

モノが中心であり、モノを最終的に所有する消費者が計測対象となる業種。**モノが世界中の場所を動く**場合、その経路のノード（作業場、加工場、工程）も採番対象となる。

`uuid-classification-rules/README.md` の用語対応（対象=logic_id/v4、記録=phys_id/v7）に準拠する。

## 業種の特性

- **中心となる価値**: モノ（SKU、原材料、製品）
- **計測の主体**: 消費者（ARPP、LTV、購入履歴）
- **モノの移動**: 世界中の場所（作業場、加工場、倉庫）を経由。トレーサビリティのノードとして採番
- **従業員・作業者**: 尊厳としては重要。データとしてはビジネス分類の軸にならない変数

## Object（対象）の採番

| 対象 | v4 | v7 | 採番なし | 理由 |
|------|-----|-----|----------|------|
| 原材料（一点一点） | ✓ | — | | 在庫・原価・トレーサビリティの単位。ビジネスが分類する点 |
| SKU（品番-カラー-サイズ） | ✓ | ✓ | | ビジネス分類の軸。作成・変更履歴の検索も必要 |
| 製品（在庫単位） | ✓ | — | | 在庫・販売の管理対象 |
| **作業場** | ✓ | ✓ | | モノが通過する場所。トレーサビリティのノード。時系列検索が必要 |
| **加工場** | ✓ | ✓ | | モノが加工される場所。トレーサビリティのノード |
| **工程** | ✓ | ✓ | | モノが通過するプロセス単位。進捗・品質の管理対象 |
| 倉庫・ロケーション | ✓ | ✓ | | 在庫の所在。入出庫の時系列検索が必要 |
| 受注伝票 | ✓ | ✓ | | 収益認識のトリガー。時系列検索が必要 |
| 消費者（ECユーザー） | ✓ | ✓ | | ARPP・LTVの主体。登録・行動の時系列検索が必要 |
| 得意先（B2B） | ✓ | ✓ | | 取引・与信の管理対象 |
| 作業員・従業員 | | | ✓ | 尊厳は重要。ビジネス分類の軸にならない。監査用は属性のみ |

## Morphism（射）の採番

| 射の種別 | 例 | v4 | v7 | 採番なし | 理由 |
|----------|-----|-----|-----|----------|------|
| **Relationship** | 受注-明細、親子BOM、工程-作業場 | ✓ | | | ビジネス分類の構造 |
| **Relationship** | モノ-作業場、モノ-工程（通過記録） | ✓ | ✓ | | トレーサビリティ。イベントごとに v4+v7 |
| **Action（収益関連）** | 購入完了、契約締結、出荷確定 | ✓ | ✓ | | 収益認識のトリガー。時系列検索が必要 |
| **Action（非収益）** | ページ閲覧、クリック | | ✓ | | 時系列・分析用 |
| **Event（監査）** | 入庫スキャン、検品通過、裁断、工程通過 | ✓ | ✓ | | 監査・トレーサビリティ。モノの通過は v4+v7 |
| **Attribute** | カラー、サイズの割当 | | | ✓ | 属性値として格納。射として実体化しない |

## モノの移動とトレーサビリティ

モノが世界中の場所を動く場合、**作業場・加工場・工程**はトレーサビリティのノードとして v4 + v7 を付与する。

| ノード | v4 | v7 | 理由 |
|--------|-----|-----|------|
| 作業場 | ✓ | ✓ | モノが通過する場所。どの作業場をいつ通過したかの記録 |
| 加工場 | ✓ | ✓ | モノが加工される場所。原産地・加工地のトレース |
| 工程 | ✓ | ✓ | 裁断、縫製、検品等。進捗・品質の管理単位 |
| 倉庫・ロケーション | ✓ | ✓ | 在庫の所在。入出庫の時系列 |

## イベント発行の例

| イベント | 対象 (v4) | 記録 (v7) | 備考 |
|----------|-----------|-----------|------|
| 原材料入庫 | 原材料ID、倉庫ID | 入庫イベントID | スキャン時に v7 発行。どの倉庫に入ったか |
| 工程通過 | 原材料ID、工程ID、作業場ID | 通過イベントID | モノがどの工程・作業場を通過したか |
| 受注登録 | 受注伝票ID、得意先ID | 受注イベントID | 稟議承認時に v7 発行 |
| 裁断（親→子） | 親パーツID、子パーツID、工程ID | 裁断イベントID | 工程通過時に v4+v7 発行 |
| 購入完了 | 受注ID、消費者ID | 購入イベントID | 収益認識のトリガー |

## 採番なしの扱い

| 対象 | 扱い |
|------|------|
| 作業員 | 監査用に `worker_id` を属性として記録する場合あり。v4 は付与しない |
| 誰が操作したか | `created_by` 等の属性。UUID は付与しない |
| 一時的な中間値 | 計算過程の変数。永続化しない |

## 3PL 倉庫・WMS における採番（補足）

ハンディターミナル（HT）によるバーコードスキャンを前提とした倉庫業務では、以下の採番ルールを適用する。**規格・コード体系**を属性として扱う。

### 倉庫で利用される規格・コード体系（属性）

| 種別 | コード体系 | 例 | 採番 |
|------|------------|-----|------|
| 商品 | JAN/EAN-13, CODE128 | 4901234567890 | 商品は v4。コードは属性 |
| ロケーション | CODE128（エリア-通路-棚-段） | 1F-A-01-3, LOC-01-02-03-04 | ロケーションは v4+v7。コードは属性 |
| 入荷伝票 | CODE128 | WH/IN/00001 | 伝票は v4+v7。コードは属性 |
| 出荷伝票 | CODE128 | WH/OUT/00001 | 伝票は v4+v7。コードは属性 |
| 内部移動伝票 | CODE128 | WH/INT/00001 | 伝票は v4+v7。コードは属性 |

### ハンディターミナル（設備）の採番

| 対象 | v4 | v7 | 理由 |
|------|-----|-----|------|
| ハンディターミナル（設備として） | ✓ | ✓ | スキャンイベントの発生源。監査・分析で「どの端末で」が必要な場合 |
| 端末の型番・OS・通信規格 | — | — | 属性として格納。1D/2D/QR、Wi-Fi/Bluetooth、IP等級等 |

### 倉庫業務フロー別イベント採番

| 業務フロー | スキャン対象 | イベント | v4 | v7 |
|------------|--------------|----------|-----|-----|
| **入荷・格納** | 入荷伝票 → 商品 → 格納ロケーション | 入荷確定、在庫移動記録 | 伝票ID、商品ID、ロケーションID | スキャンイベントID、在庫移動ID |
| **出荷・ピッキング** | 出荷伝票 → ロケーション → 商品 | ピッキング完了、梱包エリア移動 | 伝票ID、商品ID、ロケーションID | スキャンイベントID、移動ID |
| **内部移動** | 移動元ロケーション → 商品 → 移動先ロケーション | 内部移動記録 | 伝票ID、商品ID、移動元/先ロケーションID | スキャンイベントID、移動ID |
| **梱包完了** | 出荷伝票 → 梱包済み商品 | 梱包完了、ステータス更新 | 伝票ID、商品ID | 梱包完了イベントID |

### スキャンイベントの採番原則

| 原則 | 内容 |
|------|------|
| **スキャンごとに v7** | ハンディターミナルでスキャンした瞬間に v7 を発行。時系列・監査の単位 |
| **対象は v4 で参照** | スキャンされた伝票・商品・ロケーションは v4 で識別。バーコード値は属性 |
| **在庫移動は v4+v7** | 格納・ピッキング・内部移動の記録は、移動元/先ロケーション（v4）と移動イベント（v7）で表現 |
